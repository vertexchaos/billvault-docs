# Architecture diagrams

These diagrams are generated by `scripts/gen_diagrams.py`. Three are written from the code and checked
against it (`docs/diagrams/src/`); three are **derived from the code itself** so they cannot drift:
the module map (Python imports), the database schema (SQLAlchemy metadata) and the tenant lifecycle
(`_ALLOWED_TRANSITIONS`). Regenerate with `uv run python scripts/gen_diagrams.py`.

Every diagram is available as Mermaid (shown on its page, rendered natively by GitHub), SVG and Excalidraw.
The **interactive HTML** version (pan, zoom, search, trace) opens correctly on the docs site; on GitHub a
committed `.html` file would show its source, so link the docs-site page, not the file.


- Module map: Which parts of app/ import which other parts, counted from the Python source (import statements, aggregated per component).
- [Ingestion pipeline](ingestion-pipeline.md): How a document gets from an upload, a directory, a scheduled poll or a cloud-storage account to a persisted Receipt.
- Database schema: Every table and foreign key, read from the SQLAlchemy metadata in app/models.py (not typed by hand).
- [OAuth login and signup](oauth-login.md): The end-user sign-in flow for Google, Microsoft, LinkedIn (OIDC) and GitHub (OAuth2).
- Tenant billing and provisioning (Phase 21): How a Stripe subscription event reaches the tenant registry, and where the Azure deployment stamp fits.
- Tenant lifecycle: The states a tenant can be in and the moves the registry allows, read from _ALLOWED_TRANSITIONS in app/services/tenant_registry.py.
